# 02 背景と前提

> このタスクが必要になった理由、参照した上流ドキュメント、前提となる制約。

## 背景

- 結合(log-013（別ブランチ feature/server-integration）)で「サーバー→受信→表示」までは動作確認済みだが、**タイピング判定(#8)が未実装**で「打って→ダケン完了→報告」ができなかった。
- サーバー接続はサーバー側 Origin 許可待ちでブラウザから繋がらない。UI/判定の検証をこのブロッカーと切り離すため、**フロント完結テストモード**が必要。

## 前提・制約

- **責務境界**: クライアントは打鍵判定と表示のみ。コンボ/威力/相殺/KO/脱落はサーバー確定。判定はダケン単位で `DakenClearReport{dakenId,isMiss,missCount,elapsedMs}` に集約（1文字送信しない）。
- **ローマ字**: かな→ローマ字テーブルは持たない（[03](./03-判断と決定.md) 判断A）。お題を打鍵列（ローマ字/英字）として直接照合する。
- **dakenId**: サーバー発行の実IDのみ使用（捏造しない）。模擬サーバーも実発行IDを模した `mock-N` を採番し、その ID で報告する。
- **模擬サーバーは検証用スタブ**: コンボ等のダミー応答はゲームロジックの正典ではない。実挙動は必ず実サーバーで確認する。
