## 重要な判断の詳細（ADR 相当）

### 判断 A: かな→ローマ字テーブルを持たず「お題＝打鍵列」を直接照合する

- **状態 / Status**: 採用
- **日付**: 2026-07-26
- **人間承認**: 済（会話で選択肢提示 → ユーザーが「お題をローマ字/英字で直接照合」を選択）

**背景 / Context**
proto/README・AGENTS.md のセルフレビューに「ローマ字テーブルは Proto の共有データを使用（独自に持たない）／Proto へ人間承認で追加してから取り込む」と明記。一方で今セッションでフロント完結テストを動かす必要がある。

**決定 / Decision**
かな→ローマ字変換テーブルを実装せず、お題テキストを「打鍵列そのもの（ローマ字/英字）」とみなして先頭から1文字ずつ直接照合する（`src/typing/judge.ts`）。模擬サーバーはローマ字綴りの単語を出題する。

**理由 / Rationale**
Proto governance（人間承認プロセス）に抵触せず、今セッションでタイピング判定を完結できる。判定の中核（進捗・ミス・所要時間・完了検知）はローマ字テーブルの有無と独立に作れる。

**検討した代替案 / Alternatives**
| 代替案 | 却下・不採用の理由 |
|---|---|
| フロントに暫定ローマ字テーブルを実装 | 「独自に持たない」ルールに抵触。将来 Proto 版へ差し替え時に二重管理 |
| 先に Proto へローマ字テーブルを追加（正道） | 人間承認プロセスが必要で今セッションで完結しない |

**影響・トレードオフ / Consequences**
- 利点: テーブル無しで判定ロジックが完成。ローマ字お題ならブラウザで即タイピング可。
- 諦めた点: サーバーが送るかなお題（例「ねこ」）は直接照合では打鍵できない（表示は可・手動クリア報告で疎通）。本格的なかな入力は将来 Proto の RomajiTable 取り込み時に `judge.ts` を差し替えて対応。

## 保留・未決事項

- `DakenClearReport.elapsedMs` の基準時刻定義（log-013 02 Q2（別ブランチ feature/server-integration））はサーバー担当確認待ち。現状はクライアント初打鍵からの経過。
