# 05 テスト仕様

> 何を・どう確認するか。前提条件、手順、期待結果。結果は [06-テスト結果.md](./06-テスト結果.md) に記録する。

## 前提条件

- モード: `mock`（フロント完結テスト・既定）でブラウザ検証。`npm run dev` → `http://localhost:5173`。
- サーバーは不要（mock はローカル完結）。

## テストケース

| # | 種別 | 確認項目 | 手順 | 期待結果 |
|---|---|---|---|---|
| U1 | 手動(GUI) | 起動時に試合中へ遷移 | mock で起動 | 画面 `inMatch`、接続状態「フロント完結（ローカル）」、自分 `you`、お題1件表示 |
| U2 | 手動(GUI) | お題表示 | 初期表示 | お題テキスト（英字語）と「打鍵 0/n」表示 |
| U3 | 手動(GUI) | 正打鍵で進捗 | お題を正しく打つ | 打鍵済みが緑ハイライト、進捗 n/m が増加 |
| U4 | 手動(GUI) | 完了→次のお題 | お題を打ち切る | `DakenClearReport{dakenId,isMiss,missCount,elapsedMs}` 送出、次のお題が自動出題される |
| U5 | 手動(GUI) | ミス計数 | 期待でない文字を打つ | ミス数が増加、位置は進まない。次の正打鍵で `isMiss:true` が報告に反映 |

| U8 | 自動 | 判定エンジン純関数 | build | `judge.ts` の型・照合・ミス・完了検知が型検査を通る（`npm run build`） |
| U9 | 自動 | ビルド | `npm run build` | tsc + vite 成功 |
