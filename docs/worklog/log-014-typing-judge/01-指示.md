## 補足・意図の解釈

- 理想フロー = サーバーがお題送信 → フロント受信 → 画面表示 → タイピング（判定→報告）。このうち未実装だった **④タイピング判定(#8)** を作るのが主目的。
- 「切り替えられるように」= 実サーバー接続モードと、サーバー無しで完結するランダム出題テストモードを GUI で切替。
- 「フロント完結型テスト」= サーバーに依存せず、フロント内でお題生成〜ダケン判定〜次のお題までのループを回せること（結合ブロッカーの Origin 問題と切り離して UI を検証できる）。
