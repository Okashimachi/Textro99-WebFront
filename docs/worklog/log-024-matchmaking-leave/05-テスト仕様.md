# 05 テスト仕様

> 何を・どう確認するか。期待結果まで書く。

## 前提

実サーバー（Go）が無い環境のため、**検証用の最小 WebSocket サーバー**を用意した（`ws` パッケージが無いので RFC6455 の必要部分だけを実装した使い捨てスクリプト）。

| 項目 | 値 |
|---|---|
| proto ver | 本リポ同梱 `src/proto/types.ts`（v0.1.1 相当・変更なし） |
| 検証サーバー | 使い捨てスクリプト（scratchpad）。`ws://localhost:8080/ws` |
| サーバーの振る舞い | 接続を生存リストに登録。`MatchmakingJoin` で名前を確定、`MatchmakingLeave` で名前を外す、close で登録を削除。`GET /probe` で **生存接続数・参加者名・イベントログ**を返す |
| 接続先の切替 | `.env.local` に `VITE_WS_URL=ws://localhost:8080/ws`（**検証後に削除**） |

**これはサーバーの正典ではない。** 「離脱でクライアントが何を送り、接続をどう閉じるか」を観測するための計測器であり、実サーバーの待機列の実装を再現したものではない。

## 確認項目

| # | 項目 | 手順 | 期待結果 |
|---|---|---|---|
| T-1 | 型検査 | `npm run typecheck` | エラーなし |
| T-2 | 初回参加 | タイトル → プレイする → 名前 → 対戦開始 | 生存接続 1 / 参加者 1 人 / 画面の参加者一覧も 1 人 |
| T-3 | 離脱 | 「マッチングを離脱」 | ログに `MatchmakingLeave` → `close` の順。生存接続 0 |
| T-4 | 入り直し | 離脱後にもう一度 参加 | 新しい接続が 1 本開いて Join。**生存接続は 1 のまま**（2 にならない）。参加者一覧も 1 人 |
| T-5 | 反復 | T-3・T-4 を3回繰り返す | 毎回 `Leave → close → open → Join`。生存接続は常に 0 か 1 |
| T-6 | リロード | 待機中にページを再読み込み | `MatchmakingLeave` が送られてから close される |
| T-7 | 修正前との比較 | 変更を `git stash` して T-2〜T-4 を実行 | （比較のため実施） |
