## 実装の要点

### 離脱の一本化

```
待機列を離れる操作（離脱ボタン / タイトルへ戻る / キャンセル）
        ↓ すべて leaveRoom() を通る
  1. joinArmedRef = false        … open しても Join を送らない
  2. setAutoReconnect(false)     … 切った直後の再接続を防ぐ
  3. MatchmakingLeave 送信        … open のときだけ
  4. disconnect()                … 在籍の実体を消す
  5. resetGameState()            … 前セッションの一覧・盤面を残さない
```

3 と 4 の両方を行うのが要点。サーバーが「明示的な Leave」「接続の close」のどちらを契機に待機列から外しているか本リポからは分からないため、片方に賭けない設計にした。

### 呼び出し側の分担

| 呼び出し | 役割 |
|---|---|
| `net.leave`（= `leaveRoom`） | 送信・切断・state 初期化 |
| `actions.leaveMatchmaking` | 画面の後始末（intent と stage）だけ |

`ScreenRouter` の `onLeave` は既存どおり `net.leave()` → `actions.leaveMatchmaking()` の順で呼ぶ。送信が二重にならない。

### state の初期化

`@reset` は S2C ではなくクライアント都合の操作なので、`S2CAction` とは別の action 型にした。`GameAction = S2CAction | ResetAction`。

### タブを閉じる/リロード

`pagehide` で、接続が開いていれば `MatchmakingLeave` を送る。bfcache 退避でも発火するため、送るのは `status === "open"` のときだけ。
