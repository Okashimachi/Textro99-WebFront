# 03 AIの判断と決定

> AI が自律的に判断・決定したこと。「なぜその選択をしたか」を後から追えるように残す（設計判断＝ADR 相当の記録もここに溶け込ませる）。
> 軽微な決定は下の一覧表に1行で。**設計に影響する重い判断**（アーキ・依存・データ構造・後戻りコストの高い選択）は、下の「重要な判断の詳細」に節を起こして記録する。

## 決定一覧（軽微〜中）

| # | 判断・決定 | 理由 | 代替案（却下理由） | 人間承認 |
|---|---|---|---|---|
| 1 | | | | 要/不要・済 |

## 重要な判断の詳細（ADR 相当）

> 後から「なぜこうなっているか」を最も知りたくなる判断を、1判断＝1節で記録する。不要なら節ごと削除。

### 判断 A: {判断のタイトル（例: 状態管理に useReducer を採用）}

- **状態 / Status**: 提案 / 採用 / 却下 / 保留 / 置換（← どの判断を置き換えたか）
- **日付**: YYYY-MM-DD
- **人間承認**: 要/不要・済（承認者）

**背景 / Context**
> どういう問題・制約があってこの判断が必要になったか。関連する上流ドキュメントの箇所。

-

**決定 / Decision**
> 何を選んだか。

-

**理由 / Rationale**
> なぜそれを選んだか。

-

**検討した代替案 / Alternatives**
| 代替案 | 却下・不採用の理由 |
|---|---|
| | |

**影響・トレードオフ / Consequences**
> この判断で何が良くなり、何を諦めたか。将来見直す条件があれば書く。

-

## 保留・未決事項

> 判断を保留したもの、人間の確定待ちのもの。
