# 02 背景と前提

> このタスクが必要になった理由、参照した上流ドキュメント、前提となる制約。

## 背景

- log-022 で X 共有を「将来サーバー配信になる前提のモック」として実装したが、**フロントでハードコードする方針に変更**された。モック用の言い回し（差し替え TODO 等）が実態と合わなくなったため、文面を専用ファイルへ切り出して整理する必要が出た。
- log-021 で入れたセッション終端カウントダウン（15秒）が短く、リザルトを読み切る前にタイトルへ戻ってしまう。
- バッジは企画上たたみたい概念になったが、proto にはフィールドが残っている。**契約は変えられない**ため、表示だけを落とす必要がある。
- 練習モードのお題「らーめん」「ぷれいやー」が打てないことが判明。`romaji.ts` は `ー` に `-` を割り当てているのに、入力層 `useInputController` が `a-zA-Z` しか打鍵として受け付けていなかった。半角数字は `StrategySelect`（作戦選択）に予約されているため、そもそも打鍵へ届かない。
- テスト用の入口・ログが実運用画面に残っており、テストプレイの参加者に見えてしまう。

## 前提・制約

- proto のフィールドは削除しない。`badgeCount` 等は従来どおり受信し、`state` にも保持したままにする。
- 「バッジの概念を消す」はあくまで表示方針の変更であり、サーバー側の仕様変更を伴わない。
- 数字キーの扱いは rules/01 §7 と衝突する。人間の選択（指示 #2「入力キー側を許可」）に従い、**お題に数字が含まれる間だけ**打鍵へ回す限定的な例外とした。
- テストモードは削除ではなく非表示。開発時の検証手段は残す必要がある。
