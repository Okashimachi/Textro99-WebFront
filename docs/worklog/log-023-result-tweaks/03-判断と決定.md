# 03 判断と決定

> AI が下した判断、採用した案・却下した案とその理由、人間の承認。

## D-1: 文面を `src/share/postFormat.ts` に切り出した

- 「簡単に変更できるように」という要求に対し、**文面に関わるものだけ**を1ファイルに集めた。ハッシュタグ・ゲーム表示名を定数に出し、`formatPostText()` の中に本文テンプレを置いた。
- `shareText.ts` は GameOver → `ShareText` の配線だけを持つ形に縮めた。文面を変えるときに開くファイルが1つで済む。
- log-022 で書いた「サーバー配信への差し替え手順」コメントは実態と合わなくなったため削除した。

## D-2: バッジ表示を、人間が挙げた2か所より広く落とした

指示では「ランキングのところとリザルトの個人成績のところが該当しそう」だったが、`badge` を全文検索したところ表示箇所は5つあった。「概念を完全に消す」という要求に照らし、以下すべてから落とした。

| 箇所 | 対応 |
|---|---|
| `LiveRanking`（ランキング行の右端の数値） | 削除 |
| `ResultBoard`（個人成績の「最終バッジ」行） | 削除 |
| `ResultBoard`（撃破した相手の `+N`） | 削除 |
| `MatchResultScreen`（「バッジ N を献上」） | 削除 |
| `PlayerGrid99`（盤面セルの数値・tooltip の「バッジN」） | 削除（脱落の ✕ は残す） |
| `MatchStatusBar`（上部の「撃破 N バッジ」） | **タイルごと削除**（→ D-3） |
| `reducer`（撃破イベントの文言 `（+N）`） | 削除 |

いずれも**表示だけ**を消し、proto の受信・`state` への保持は変更していない。

## D-3: 上部バーの「撃破」タイルは、値がバッジ数だったため取り下げた

- `MatchStatusBar` の「撃破」は、ラベルこそ撃破だが**値は `badgeCount`**（単位も「バッジ」）だった。バッジを出さない方針では、この値をそのまま別ラベルで見せると意味が変わってしまう。
- 撃破数として正しい値（`GameOver.koCount` 相当）は**試合中には配信されていない**。クライアントで `KoNotified` を数えると勝敗数値のローカル算出に寄る（rules/01 §1）。
- よってタイルごと落とし、コメントで復活条件（サーバーが試合中の撃破数を配信するようになったら）を残した。**この判断は人間の指示範囲を超えるため、報告時に明示する。**

## D-4: テストモードは削除せず `?test=1` で隠した

- 「非表示にしておいて下さい」＝ 削除ではないと解釈。`TitleScreen` の `onTest` を任意 prop にし、URL に `?test=1` があるときだけ渡す形にした。
- これにより通常のプレイヤーには入口が見えず、開発時は URL 一つで従来どおりテストモード（モード選択・練習・開発ツール・Devモック注入）に入れる。
- 副次効果として、入口が常に `play` になるため `devToolsAvailable` が false になり、**マッチング画面のイベントログ（テスト用）も自動的に出なくなる**。加えて `ScreenRouter` 側でも `showDevTools` が false なら `events` を渡さないよう明示的に塞いだ。

## D-5: 数字キーは「お題に数字が含まれる間だけ」打鍵へ回す（人間が選択）

- 提示した3案から人間が「入力キー側を許可」を選択（指示 #2）。
- rules/01 §7（操作は2種のみ）に対する例外になるため、**無条件には広げず**、現在のお題に `[0-9]` が含まれる間だけ打鍵に回す形にした。それ以外は従来どおり `StrategySelect`。
- 判定（お題に数字があるか）は、お題を知っている `App` 側で行い、入力層は渡された `digitsAsDaken` に従って振り分けるだけにした。入力層にお題の知識を持たせない。
- 伸ばし棒は `isDakenChar` に `-` を追加するだけで解決した（`romaji.ts` 側は既に `ー → "-"` を持っていた）。

## D-6: dev モックのお題に数字・伸ばし棒入りを追加した

- 数字入りのお題が dev スタブに1つも無く、振り分けを検証できなかったため、`てきすとろ99` / `こーひー` を追加した。dev 専用スタブであり、ゲーム内容の正典ではない（rules/02 §2）。

## 人間の承認

| 判断 | 承認状況 |
|---|---|
| D-5（数字キーの扱い） | 指示 #2 で選択済み |
| D-1 / D-2 / D-4 / D-6 | 指示の範囲内。実装報告時に説明 |
