# 03 判断と決定

## 決定

1. **カラートークンを tailwind.config.js に追加**（`paper` / `panel` / `head` / `line` / `ink` / `sub` / `accent` / `ok` / `warn`）。
   個々のコンポーネントに生の hex を散らさず、後からテーマを差し替えられる状態にする。
2. **`Panel` 共通コンポーネントを新設**（`src/components/hud/Panel.tsx`）。
   モック画像の「色チップ＋ラベル＋右端の補助情報」を持つヘッダ帯を1箇所に集約する。
3. **AttackWarningBar を盤面のオーバーレイから右列の常設パネルへ移動**。
   モックの `IN — 被弾予告` に合わせ、予告 0 件でも枠を残す（レイアウトが跳ねない）。
4. **PlayField から「天井がせり下がる」演出を撤去**し、被弾スタックを横セグメントバーに変更。
   モックの表現に合わせ、NEXT は縦積みカードから行リストへ。
5. **ComboGauge のリングメーターを廃し、OUT パネル（大きな数値＋10段ブロック）に変更**。
   コンポーネント名・props は据え置き（用語集・呼び出し側を変えない）。
6. **セットアップ／マッチング／リザルト画面も同じ白地テーマへ**追従（暗色のままだと同一アプリに見えないため）。
   `RawStateDebugPane` は開発用オーバーレイなので暗色のまま残す。

7. **独自カラートークン（`accent` 等の theme.extend）をやめ、Tailwind 標準パレットだけで組む。**
   初回実装では `tailwind.config.js` にトークンを追加したが、**config 変更は dev サーバー再起動が要る**ため、
   起動済みのサーバーでは新クラスが生成されず「色が全部消える（素の黒白）」状態になった。
   標準パレット（zinc / red / amber / emerald / sky）だけなら再起動なしで常に色が出る。
8. **配色に意味を持たせる**（無彩色ばかりにしない）:
   赤=自分の攻撃・危険 / 琥珀=注意・撃破バッジ・MAX / 緑=安全・打鍵確定 / 青=お題と作戦（情報系） / 黒=脱落・自分の行。
   パネルのヘッダ帯も役割色で塗り分け、視線がどのパネルの話か即分かるようにした。

9. **配置を「中央の主ディスプレイ固定」に再構成**（人間の指示）:
   - 中央: 作戦（上）→ 主ディスプレイ（いま打つお題）→ 攻撃力 OUT（下）。視線移動を縦一列に収める。
   - 左: 敵の状況（99人グリッド）／被弾予告 IN／戦況ログ。
   - 右: NEXT（下端が「次」で上へ積み上がる）／ランキング。
   これに伴い **NEXT を PlayField から `NextQueue.tsx` に分離**（1パネル1役割）。
   `PlayField` は被弾スタックと現在のお題＋打鍵進捗だけを持つ。
10. 練習モード（`src/dev/mockServer`）が常に1件しかお題を持たず NEXT を確認できなかったため、
   実サーバー同様に**数件先まで積む**よう先読み発行を追加した（開発用スタブの挙動のみ）。

11. **視認性の強化（人間の指示）**:
   - ヘッダは「残り人数」「撃破数」だけに絞り、色付きの大枠＋5xl の数字で強調（順位/難易度/MATCH ID は削除）。
   - NEXT は**ひらがなのみ**に簡略化（種別ラベル・Lv・ローマ字を削除）し、種別は色で区別＝多くの件数を縦に並べられる。
   - **被弾予告パネルを廃止**（`AttackWarningBar.tsx` を削除）。飛来する攻撃はトラップ／被弾ダケンとして
     NEXT に色付きで並ぶため、専用パネルは二重表示だった。
   - **被弾スタックパネルも廃止**（`DakenStackView.tsx` を削除）。溜まり具合は NEXT 左のレールが担い、
     ヘッダ右に「あと N でゲームオーバー」を出す＝NEXT を見るだけで残余が分かる。
   - コンボは主ディスプレイ右下の**円形バッジ**へ統合（`ComboGauge` はパネル → バッジに作り替え）。
   - 99人グリッドは**常に 99 マス**を描き、未参加の席は破線＋✕ の「欠席」にした（練習/少人数でも盤面が崩れない）。
   - 戦況ログは主ディスプレイ直上の**通知**に変更。種類ごとに色とタグ（撃破/攻撃/相殺/決着/情報）を出す。
   - 注記: `incomingAttacks` は ViewModel 側に残している（サーバー由来データを捨てない）。表示だけをやめた。

## 却下した案

- 画像内の「攻撃効果ログ」等、サーバーが配信していない値を新設すること
  → 表示のためにクライアントで戦闘値を作ることになるため却下。既存の `GameEvent` の範囲で表現した。
- ダークテーマとの二重管理（`dark:` バリアント）→ 今回はモックの1テーマに絞る。
