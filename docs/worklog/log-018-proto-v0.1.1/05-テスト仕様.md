# 05 テスト仕様

> 何を・どう確認するか。前提条件、手順、期待結果。自動テスト/手動テストの別。結果は [06-テスト結果.md](./06-テスト結果.md) に記録する。

## 前提条件

- proto v0.1.1（`66e00fb`）
- **L系（ローカル検証）**: `npm run dev` + アプリ内の実行モード `mock`（フロント完結）。サーバー不要。
- **S系（実サーバー結合）**: `VITE_WS_URL` を実サーバーに向け、実行モード `server`。**server #77 / #80 が実装済みであることが前提**。
  - 2026-07-31 時点で Render のサービスが suspended（`x-render-routing: suspend` で即 503）のため S 系は実施不能。

## テストケース

| # | 種別 | 確認項目 | 手順 | 期待結果 |
|---|---|---|---|---|
| L1 | 自動 | 型整合 | `npm run typecheck` | エラー 0。削除された型への参照が残っていない |
| L2 | 自動 | ビルド | `npm run build` | 成功。未解決 import なし |
| L3 | 手動 | Enter が無反応 | mock で試合中に Enter を連打 | 何も送信されず、コンソールに `AttackRequest` の送信ログが出ない。画面が壊れない |
| L4 | 手動 | 0-9 は従来どおり | mock で 0〜9 を押す | `StrategySelect` が送信され、戦略表示が変わる |
| L5 | 手動 | 被弾予告の表示と自然消滅 | mock で `AttackIncoming` を発火 | 予告が残り時間つきで出て、`graceMs` 経過後に自動で消える。手動消化の操作は不要 |
| L6 | 手動 | 予告が溜まり続けない | mock で `AttackIncoming` を10件以上連続発火し、grace 経過後に state を確認 | `incomingAttacks` に期限切れが蓄積しない |
| L7 | 手動 | `insertIndex` の割り込み | mock で `insertIndex` 付き `DakenIssued` を発火 | 指定位置にダケンが割り込む。範囲外の値でもクラッシュせず端にクランプされる |
| L8 | 手動 | 順位表示 | mock で `rank` 付き `PlayerListUpdated` を流す | サーバー値の昇順で並ぶ。`rank=0` は末尾。自分の行が強調される |
| L9 | 手動 | KO ログの表示名 | mock で `KoNotified` を発火 | 接続ID ではなく displayName で「A が B を撃破」と出る。未知IDのみ ID 表示 |
| S1 | 手動 | 実サーバーで名前が反映 | server モードで名前を入れて参加 | 盤面に接続IDではなく入力した表示名が出る |
| S2 | 手動 | 攻撃の自動発火 | server モードでダケンをノーミスクリア | Enter を押さずに相手へ攻撃が飛ぶ（相手側に `AttackIncoming`） |
| S3 | 手動 | 実サーバーの順位 | server モードで試合を進行 | ランキングがサーバー確定順位と一致し、脱落者が下位へ移る |
| S4 | 手動 | 被弾の着弾 | server モードで被弾予告を受ける | grace 経過後に `DakenIssued` / `DakenStackUpdated` が届き、予告表示が消える |
