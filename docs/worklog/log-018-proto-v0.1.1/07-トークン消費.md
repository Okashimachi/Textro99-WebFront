# 07 トークン消費

> このタスクで消費したトークンと、その原因・過程。コスト効率を後から改善するための記録。

## サマリ

| 項目 | 値 |
|---|---|
| 概算トークン消費 | 入力 ~120k / 出力 ~15k（起票・整理セッション分のみ。実装セッション分は記録なし） |
| セッション往復数 | 5（うち本タスクに直接関わるのは 2） |
| 手戻り回数 | 1（作業ブランチの状態を誤認し、訂正） |
| 主な消費要因 | 別件（PR #49 / 503 調査）の探索 + 未コミット差分の全読み込み |

## 消費の過程・原因の分析

- 本セッションは proto 追従の**実装ではなく起票・整理**。実装そのもののトークン消費は記録が残っていない。
- 前半（往復 1〜3）は本タスクと無関係な PR #49・503 の調査に費やした。`curl` でサーバー応答ヘッダを見た時点で `x-render-routing: suspend` が判明し即決着したので、ここは効率的だった。逆に、それ以前に `git log` / `git diff` を複数回に分けて叩いたのは1回にまとめられた。
- **手戻り 1件**: 往復1で「作業ブランチの `connection.ts` は修正前」と誤って報告した。`git diff HEAD origin/main` の出力を差分の向きを確認せずに読んだのが原因。往復4で実ファイルを読んで誤りに気づき訂正した。**差分の有無ではなく、内容を直接 grep して確認すべきだった**。
- 未コミットの18ファイルを把握するため差分をほぼ全読みした。作業ログが着手時に起票されていれば、02/03 を読むだけで済んだ。

## 次回への改善案

- ブランチの状態確認は `git diff --stat` の行数ではなく、**対象シンボルを直接 grep** して事実を取る（`git show <ref>:<path> | grep -c <symbol>`）。
- 独立した `git` 調査コマンドは1回のツール呼び出しにまとめる。
- **着手時に作業ログを起票する**（AGENTS.md §3 の本来の運用）。今回のように後から差分だけで経緯を復元すると、01-指示が埋められず記録の質が落ちる。
