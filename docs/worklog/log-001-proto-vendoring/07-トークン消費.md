# 07 トークン消費

> このタスクで消費したトークンと、その原因・過程。コスト効率を後から改善するための記録。
> Claude Code は正確な数値を自動保存しないため、`/cost` の値を人間が転記するか AI が概算を記入する。

## サマリ

| 項目 | 値 |
|---|---|
| 概算トークン消費 | 入力 ~多め / 出力 ~中（正確値は `/cost` を人間が転記） |
| セッション往復数 | 数往復（方式選択→ブランチ→起票→取り込み→検証） |
| 手戻り回数 | 1（Write 前に Read 必須のツール制約で書き直し数回） |
| 主な消費要因 | ①検証 diff の出力が全行差分（CRLF 差）で**巨大なログを2回展開**した ②`types.ts` 全文を出力に再掲した |

## 消費の過程・原因の分析

- 最大の無駄は **テスト時の diff 出力**。CRLF 差により 223 行×2 の全行差分が丸ごと出力に載り、その後もう一度 `tr -d '\r'` で比較し直したため、同じ内容を実質2回展開した。
- `types.ts`（約220行）を vendored ファイルとして**全文書き出した**のは手コピー方式の性質上不可避。ただし検証段階での再表示は避けられた。
- worklog テンプレの各ファイルが「Write 前に Read 必須」のため、コピー直後のファイルを1つずつ読み直す往復が発生した。

## 次回への改善案

- 一致検証は最初から改行差を無視する比較（`diff <(tr -d '\r' ...)` や `git diff --no-index --ignore-cr-at-eol`）を使い、**全行差分の巨大出力を出さない**。
- あるいは `cmp -s` やハッシュ比較（`sha256`、CR除去後）で「一致/不一致」だけを取得すれば出力は1行で済む。
- 手コピー方式は本質的に全文出力を伴うため、頻繁に更新するなら **git 直参照/npm 依存への移行でこのコストを消せる**（判断 A の見直し条件に対応）。
