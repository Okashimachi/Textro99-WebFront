# 02 背景と前提

> このタスクが必要になった理由、参照した上流ドキュメント、前提となる制約。

## 背景

- WebFront は proto の DTO 型を参照して WebSocket で通信する（サーバー権威・受信 state を描画）。実装を始める前に「型をどこから・どの形で取り込むか」を確定する必要がある。
- Proto は v0.1.0 が定義済みだが**未リリース（未 publish）**。GitHub Packages の設定は入っているが認証・CI 未整備。ハッカソン初速を優先し、レジストリ整備を待たずに型を使えるようにしたい。

## 前提・制約

- **契約はこのリポジトリで変更しない**（[docs/rules/01](../../rules/01-責務と絶対原則.md)）。取り込んだ型は proto の写しであり、web 側で編集しない。
- `types.ts` は `MessageType` という**実行時コード（const）を含む**。純粋な型のみではないため、単なる `import type` だけでは足りないケースがある（値としても import され得る）。
- **ローマ字データは今回スコープ外**。打鍵判定 lib 実装時に Proto へ追加依頼（人間承認フロー）する前提。
