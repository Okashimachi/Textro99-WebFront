## 重要な判断の詳細（ADR 相当）

### 判断 A: proto の TS 型を「手コピー（vendoring）」で取り込む

- **状態 / Status**: 採用（人間が選択肢から決定）
- **日付**: 2026-07-23
- **人間承認**: 済（配布方式の選択肢提示に対し「型ファイルを手コピー」を選択）

**背景 / Context**
proto v0.1.0 は未 publish。GitHub Packages 配布は認証・CI 整備コストがハッカソン初速に対して重い。一方 `types.ts` はソース直配布形式で、単体ファイルとして完結している。

**決定 / Decision**
proto の `ts/types.ts` を web リポジトリの `src/proto/types.ts` に手でコピーして取り込む。npm 依存・レジストリは当面使わない。

**理由 / Rationale**
- 単一ファイルで完結し、コピーだけで即座に型を使える（初速最大）。
- レジストリ認証・`.npmrc`・publish 権限・CI が一切不要。
- 生 `.ts`（`MessageType` 定数を含む）を node_modules から読む際の Vite トランスパイル問題を回避できる（自前 src 内なら通常のビルド対象）。

**検討した代替案 / Alternatives**
| 代替案 | 却下・不採用の理由 |
|---|---|
| git 直参照（`github:...#v0.1.0`） | レジストリ不要で版固定できるが、生 `.ts` を node_modules から読む Vite 設定の追加調整が要る。初速では手コピーが単純 |
| GitHub Packages で publish | 正規だが認証・CI 整備が重い。proto も未リリース。今は時期尚早 |

**影響・トレードオフ / Consequences**
- 利点: 依存ゼロで最速。ビルド設定を汚さない。
- 代償: **proto と web の型が二重管理**になる。proto 更新時に手で同期しないと版ズレする → `src/proto/README.md` に同期手順と現在版を明記して運用で吸収する。
- 見直し条件: proto が publish 運用に乗り、認証・CI が整ったら npm 依存（版固定）へ移行する。移行タスクを別 log で起票する。

- ローマ字データの Proto への追加（打鍵判定 lib 着手時）。
