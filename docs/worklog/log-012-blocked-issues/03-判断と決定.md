# 03 判断と決定

## #8 打鍵判定 TypingJudge — 上流ブロック

- Issue 本文どおり **proto に共有ローマ字テーブルが未実装**。docs/rules/01 §2 は「判定は Proto の共有ローマ字テーブルデータで実装し、web に独自テーブルを二重管理しない」と定める。
- したがって **web に暫定ローマ字テーブルを作らない**（規約違反になる）。TypingJudge 本体の実装は、Proto へローマ字データが追加され参照版を上げるまで着手しない。
- **先行して用意した差込点**（#7 / log-007）:
  - 入力送信層 `useInputController` が文字キーを `onCharKey(char)` として公開済み。
  - `DakenClearReport`（`@/proto/types`）はミラー済みで、判定確定時にダケン単位で送る接続先が明確。
  - 表示側 `DakenDisplay` は表示専用 `typedPrefix` を受け取れる。
- **人間対応が必要**: Proto 側の人間承認フローで共有ローマ字テーブルを追加 → 本リポの proto 版を上げる → その後 TypingJudge を `onCharKey` に接続して実装。

## #14 静的ホスティング＋PRプレビュー — 外部アカウント依存

- Vercel / Cloudflare Pages への接続、および PR プレビュー URL 発行は **ホスティング事業者アカウントとリポジトリ連携（人間の権限）** を要する。AI はアカウント接続・秘密情報設定を行わない（安全方針・docs/rules/03）。
- 本リポ側の準備状況:
  - 静的ビルドは `npm run build`（`tsc -b && vite build`）で `dist/` を生成可能（本セッションで成功確認）。プロバイダ非依存。
  - 接続先は環境変数 `VITE_WS_URL`（`.env.example` あり、`.env` は gitignore 済み）。**本番URL・トークンはコミットしない**。
- **人間対応が必要**: Vercel/Cloudflare のプロジェクト作成と GitHub 連携、環境変数 `VITE_WS_URL` の各環境設定。連携後は push 毎デプロイ／PR プレビューが自動化される。ビルド設定（Framework: Vite / Build: `npm run build` / Output: `dist`）をそのまま使える。
