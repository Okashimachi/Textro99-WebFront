# 03 AIの判断と決定

> AI が自律的に判断・決定したこと。「なぜその選択をしたか」を後から追えるように残す（設計判断＝ADR 相当の記録もここに溶け込ませる）。

## 重要な判断の詳細（ADR 相当）

### 判断 A: 「試合が完全に終わった」の判定を **サーバーの切断** に置く

- **状態 / Status**: 採用
- **日付**: 2026-08-01
- **人間承認**: 済（指示 #2）

**背景 / Context**
15秒カウントダウンを始めるには「試合全体が終わった」瞬間が要る。しかし proto には MatchEnd 相当が無い（[02](./02-背景と前提.md) 参照）。クライアント側で判定するなら `aliveCount <= 1` や自分の `rank == 1` を使うことになるが、これは「残り1人で試合終了」という**勝敗ルールをクライアントが持つ**ことを意味し、docs/rules/01 §1,§3 に抵触する。

**決定 / Decision**
自分の GameOver 後は自動再接続を止めたうえで、**接続が closed になったこと**（＝サーバーが終端を告げた）をシグナルとして15秒カウントダウンを開始する。判定は `src/screens/sessionEnd.ts` の `isConnectionFinished()` 1関数に閉じ込める。

**理由 / Rationale**
クライアントは一切の勝敗判定を持たず、サーバーの振る舞いをそのまま写すだけになる。将来 proto に MatchEnd が入ったら、この1関数を差し替えるだけで移行できる。

**検討した代替案 / Alternatives**
| 代替案 | 却下・不採用の理由 |
|---|---|
| `aliveCount <= 1` / 自分の `rank == 1` で判定 | 勝敗ルールのクライアント実装になる（rules/01 §1,§3） |
| 上流に MatchEnd を追加してから実装 | 契約変更は Proto 側＋人間承認の作業。バグ修正を待たせることになる |

**影響・トレードオフ / Consequences**
- **要検証（残課題）**: サーバーが**自分の脱落時点**で接続を切る実装だと、脱落者は観戦もランキング閲覧もできず、脱落と同時にカウントダウンへ入ってしまう。その場合は「試合完全終了まで接続を維持する」サーバー側の対応が必要。実サーバーでの close タイミング実測は未了。
- サーバーが試合終了後も接続を維持し続ける実装の場合、カウントダウンは始まらない（＝自動でタイトルへ戻らない）。ただし決定 4〜6 により**次の試合へ送り込まれることはなく**、ユーザーは「タイトルへ」「再マッチング」で明示的に抜けられる。
