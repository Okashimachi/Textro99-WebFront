# 07 トークン消費

> このタスクで消費したトークンと、その原因・過程。コスト効率を後から改善するための記録。
> Claude Code は正確な数値を自動保存しないため、`/cost` の値を人間が転記するか AI が概算を記入する。

## サマリ

| 項目 | 値 |
|---|---|
| 概算トークン消費 | 入力 ~200k（キャッシュ込み） / 出力 ~25k |
| セッション往復数 | 約 45（うちブラウザ操作が約 15） |
| 手戻り回数 | 2（観戦バナーの誤文言／ブラウザのポート・ref 取得） |
| 主な消費要因 | 現状把握のための関連ファイル一括読み込み（App / lifecycle / reducer / connection / ScreenRouter）／ブラウザ検証時の `document.body.innerText` 全文取得 |

## 消費の過程・原因の分析

- 方針立案の前に、画面フロー・接続・reducer を横断して読む必要があった。ここは並列読み込みで往復数は抑えたが、`reducer.ts` 全文など読み込み量は大きい。
- ブラウザ検証で `preview_start` が割り当てたポート（58616）と Vite の実ポート（5174）がずれ、タブが戻る現象で数往復を空費した。最終的に `javascript_tool` で直接ボタンを叩く方式に切り替えて安定した。
- 検証時に `document.body.innerText` を丸ごと返したため、RawStateDebugPane の JSON まで含む大きな出力を1回取り込んだ（最大の単発消費）。

## 次回への改善案

- ブラウザ検証は最初から `javascript_tool` でセレクタ操作＋**必要な要素だけの textContent** を返す（`innerText` 全文を取らない）。RawStateDebugPane が開いている画面では特に効く。
- dev サーバーは `.claude/launch.json` の port が埋まっている場合にポートがずれるので、最初に `preview_logs` で実ポートを確認してから navigate する。
