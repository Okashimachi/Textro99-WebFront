# 05 テスト仕様

> 何を・どう確認するか。前提条件、手順、期待結果。結果は [06-テスト結果.md](./06-テスト結果.md) に記録する。

## 前提条件

- ローカル dev サーバー（`npm run dev`）。ブラウザで `テスト用 → 練習（フロント完結） → 練習開始`。
- 練習モードでは Dev モックの「13. GameOver (優勝)」で S2C を手動注入できる。
- T5〜T7（実サーバー系）は `VITE_WS_URL` を設定し、`--mode match` のサーバーに複数人で接続して実施する。

## テストケース

| # | 種別 | 確認項目 | 手順 | 期待結果 |
|---|---|---|---|---|
| 1 | 手動(GUI) | 型・ビルド | `npx tsc --noEmit` | エラー 0 |
| 2 | 手動(GUI) | GameOver でリザルトがモーダル表示される | 練習開始 → GameOver 注入 | 観戦画面の上にリザルトが重なる。`inputActive: false` |
| 3 | 手動(GUI) | 閉じるとランキング・敵の状況が見える | モーダルの「戦況を見る」 | 画面: spectating。ランキング／99人グリッド／戦況ログが見える。右下に「リザルトを見る」 |
| 4 | 手動(GUI) | 終了カウントダウン → タイトル | 終端シグナル成立後に放置 | 「試合が終了しました。N秒後にタイトルへ戻ります」が減り、0 でタイトルへ戻る |
| 5 | 手動(実サーバー) | リザルト放置で次試合に入らない | 実サーバーで試合終了後、2〜3分放置 | 試合中画面に戻らない。`MatchmakingJoin` が送信ログに出ない |
| 6 | 手動(実サーバー) | 脱落後もランキング／敵の状況が更新され続ける | 先に脱落し、他プレイヤーが打ち続ける | 背後の順位・グリッドが更新される（＝サーバーが試合完全終了まで接続を維持している） |
| 7 | 手動(実サーバー) | 再マッチング / タイトルへ | それぞれのボタンを押す | 再マッチング＝待機画面へ（接続を張り直して再登録）。タイトルへ＝接続が切れてタイトル |
