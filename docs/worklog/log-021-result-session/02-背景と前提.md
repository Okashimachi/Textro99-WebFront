# 02 背景と前提

> このタスクが必要になった理由、参照した上流ドキュメント、前提となる制約。

## 背景

- リザルトは `ScreenPhase = "result"` という**排他フェーズ**として実装されていた（log-006 / log-011）。試合画面を丸ごと置き換えるため、リザルト表示中はランキング・敵の状況（サーバーのブロードキャスト）が一切見えない。
- 一方で GameOver 後も接続は生きており、`WsConnection` は `autoReconnect: true`、かつ **open のたびに無条件で `MatchmakingJoin` を送っていた**（`App.tsx` の `onStatusChange`）。そのため放置しているだけで次の試合に登録され、`MatchStart` を受けると reducer が `gameOver: null` に戻す → `deriveScreenPhase` が `inMatch` を返す、という経路で試合中へ引き戻されていた（報告されたバグ）。
- 引き戻しの経路は2通り考えられる（①サーバーが試合終了時に接続を切る → autoReconnect が再接続して再参加／②サーバーが同一接続をプールへ戻して次の MatchStart を送る）。実サーバーでの実測は未了のため、**どちらでも止まる**ように塞いだ。

## 前提・制約

- 契約（proto）はこのリポジトリで変更しない。よって「試合が完全に終わった」を表すメッセージは追加できない。
- 打鍵判定以外のゲームロジックをクライアントに書かない。したがって `aliveCount <= 1` のような**勝敗ルールの再実装は避ける**。
- 終端シグナルは人間の判断で **「サーバーが接続を切ったこと」** を採用（指示 #2）。
