# 08 振り返り

> 得られた知見、次に活かすこと、上流（Docs/Proto/Client-Docs）へ還元すべき候補。

## 知見

- **「サーバーに移す前提のクライアント実装」は、捨てる範囲を1ファイルに閉じるのが最重要**だった。`ShareText` 型を挟んで UI との境界を作ったので、サーバー配信へ移行しても UI 側は無変更で済む。
- 指示の字面（「XのAPIを叩いて」）と、実現したい体験（「ポストする直前まで行ける」）が食い違うケースだった。**体験のほうを要件と読み、字面との差分を明示して報告する**形で処理した。API 方式はリポジトリのルール（秘密情報を差分に含めない／環境変数で切替）と真っ向から衝突するため、そもそも選べなかった。
- 共有文面のような「表示テキスト」も、値の由来をたどると責務境界の話になる。正確率を入れなかった判断（D-3）は、表示計算を2か所に持たないための線引き。

## 次に活かすこと

- ブラウザ検証は、UI をクリックで辿るより **`javascript_tool` で目的の DOM を直接叩くほうが速い**。特に多段の画面遷移を経る検証では最初からこちらを選ぶ。
- dev サーバーは起動ログで実ポートを確認してから操作する（別セッションとのポート競合が起こりうる）。
