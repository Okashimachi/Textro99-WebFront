# 07 トークン消費

## サマリ

| 項目 | 値 |
|---|---|
| 概算トークン消費 | 入力 ~90k / 出力 ~12k |
| セッション往復数 | 2（確認1回 + 実装） |
| 手戻り回数 | 0 |
| 主な消費要因 | ブラウザ検証の往復（画面遷移を実際に踏むため read_page / screenshot を反復） |

## 消費の過程・原因の分析

- 着手前に既存の画面フロー（`App.tsx` / `useScreenPhase` / `MatchmakingScreen` / `ScreenRouter` / setup 配下）をまとめて読んだ。ここは省けない前提把握。
- **実装前に proto と rules を確認したのが効いた**。`countdownMs` の存在と Room 契約の不在を先に押さえたことで、フロントに30秒タイマーを実装してから作り直す手戻りを避けられた（確認1往復のコストで実装1周分を節約）。
- ブラウザ検証で消費が伸びた。特に待機画面の2状態に到達しようとして、実サーバー/モックの両経路を試して届かなかった探索が無駄になった。

## 次回への改善案

- 到達したい画面状態が「サーバー都合で再現できない」可能性を先に見積もる。今回は `mockServer` が `MatchmakingStatus` を送らないことを**先に grep していれば**、モック経由の試行を省けた。
- 画面遷移の検証は read_page（構造確認）と screenshot（見た目確認）を使い分ける。今回は両方撃っていた場面がある。
