# 02 背景と前提

## 背景

- これまでのタイトル画面は「はじめる」1つで、必ずモード選択（オンライン/練習）を経由する開発用フローだった。実運用でプレイヤーに見せる導線としては、モード選択も開発ツールも不要。
- 実運用の導線（プレイする → 名前入力 → マッチング待機 → 試合）と、開発用の導線（テスト用 → モード選択 → …）を入口の時点で分ける必要がある。

## 前提・制約

- **試合開始のタイミングはサーバー権威**。サーバーが最低人数の到達を検出してカウントダウンを開始し、`countdownMs` で残り時間を配信する。フロントはそれを描画するだけで、ローカルで秒数を数えて開始しない。
- **「部屋」は作らない**。proto に Room 契約が無いため、実プレイ導線は既存のグローバルキュー（`MatchmakingJoin` → `MatchmakingStatus` → `MatchStart`）に乗せる。部屋制は契約が入ってからの継ぎ目として残す。
- 30秒という具体的な秒数はサーバー設定値。フロントには持たせない。
