# 07 トークン消費

## サマリ

| 項目 | 値 |
|---|---|
| 概算トークン消費 | 入力 ~250k / 出力 ~15k（セッション全体。log-019 相当の調査フェーズを含む） |
| セッション往復数 | 40 前後 |
| 手戻り回数 | 2（テスト仕様 #6 / #2 で見つけた表示不具合の修正） |

## 消費の内訳・原因

- 本タスク単体の実装は小さいが、**同一セッションでリザルト周りの設計相談を先に行っていた**ため、
  App / lifecycle / reducer / proto を一通り読んだぶんの入力が積み上がっている。
- 上流（Proto / Server）の差分確認に `git log` / `git show` を複数回。ここは必要な確認だった
  （`countdownMs` の意味変更を読み違えると表示が壊れるため）。
- ブラウザ検証で実サーバーのマッチングを 4 回試行。1 回目はカウントダウン（5 秒）を取り逃がし、
  ポーリング用の JS がハングして 30 秒タイムアウトした。

## 改善案

- 実サーバーのマッチング待機は「2 クライアント同時 + 短いカウントダウン」で観測が難しい。
  **Dev モック注入で先に描画を固めてから実サーバーで裏取り**する順にすると試行回数を減らせる
  （今回は逆順でやってしまった）。
- ブラウザ側で長時間ループを回す JS は避け、`setInterval` + 後読みにする（今回の後半の方法が正解）。
