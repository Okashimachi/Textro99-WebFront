## 重要な判断の詳細

### 残り時間のローカル補間は「戦闘ロジック」に当たらないか

docs/rules/01 §1,§3 は「戦闘・ゲームルールの判定をクライアントに書かない」「描画は受信 state 経由」。
今回の補間は **表示専用の時計** であり、次を満たすので原則に反しないと判断した。

- 試合開始の**判定はしていない**。画面は `MatchStart` を受信するまで待機のままで、
  残り 0 になっても自分から試合中へ遷移しない（0 到達時は「まもなく開始します…」を出すだけ）。
- 補間の基準はサーバーが送った `countdownMs` そのもの。クライアントは値を作らない。
- 既存の `IncomingAttacks` / `useDakenTimer` と同じ「サーバー値 + 受信時刻をローカル時計で描く」パターンを踏襲。
