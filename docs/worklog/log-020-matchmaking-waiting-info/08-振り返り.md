# 08 振り返り

## うまくいった点

- 上流の差分（Proto `54ddfb9` / Server `6c33138`）を**サーバー実装まで読んで**から着手したので、
  「status は join/leave 時にしか配信されない」＝ローカル補間が必須、という前提を実装前に掴めた。
- log-019 で残り秒数表示を消した理由がコメントとして残っていたため、
  「なぜ今なら戻せるのか」をコメントに書き換える形で素直に復活できた。

## 詰まった点 / 反省

- 実サーバーのカウントダウンが 5 秒しかなく、ブラウザ検証で 2 回取り逃がした。
  Dev モック注入なら 15 秒で確実に観測できたのに、実サーバーから試したのは効率が悪かった。
- 「参加者一覧を常に出す」を素直に実装したら、`MatchStart` 後の 3 秒ゲートで
  `matchmaking: null` になり空表示になった。**state のライフサイクル（いつ null に戻るか）**を
  先に確認すべきだった。

## 上流への還元候補

- `MatchmakingStatus` は join/leave 時のみ配信という仕様を、プロトコル仕様書に明記したい
  （クライアントは残り時間をローカル補間する必要がある、という実装指針とセットで）。
  Unity 側も同じ補間が必要になるため、Client-Docs に「受信時刻 + countdownMs を締切にする」
  パターンとして書いておくと二重に悩まずに済む。
- サーバーの `StartCountdownMs` はデプロイ環境で 5000。テスト時に観測しづらいので、
  検証用に一時的に伸ばせると助かる（config-front から変更可能か要確認）。
