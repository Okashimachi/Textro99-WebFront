# docs/worklog — AI作業ログ

AI（Claude Code / Codex / Cursor 等）に出した指示・AIの判断と決定・テスト仕様と結果・トークン消費を、**1タスク＝1ディレクトリ**で記録する場所。記録は関心事ごとにファイルへ切り分ける。

## 目的

- 「なぜこの実装になったか」「どの指示から生まれたか」を後から追える状態にする（AI生成コードの意思決定ログ）。
- テスト仕様と結果を残し、回帰時の確認点を明確にする。
- **トークン消費量とその原因/過程を記録し**、コスト効率の悪い進め方を可視化・改善する。

## 命名規則

```
docs/worklog/log-NNN-{短いkebab-caseの主題}/
```

- `NNN` は3桁連番（`001` から。**欠番を作らない**）。
- 例: `log-001-webfront-scaffold/` / `log-002-daken-display-component/`
- テンプレートは [_template/](./_template/)。新規タスク着手時にこのディレクトリごとコピーして番号・主題にリネームする。

## ディレクトリ内の構成（関心事ごとに切り分け）

| ファイル | 内容 | 記入タイミング |
|---|---|---|
| `README.md` | メタ情報（状態・担当AI・日付・ブランチ）と入口 | 着手時 |
| `01-指示.md` | 人間 → AI の指示 | 着手時 |
| `02-背景と前提.md` | 背景・参照した上流ドキュメント・制約 | 着手時 |
| `03-判断と決定.md` | AIの判断・決定・却下案・人間承認 | 作業中〜完了 |
| `04-成果物.md` | 変更ファイル・実装要点 | 完了時 |
| `05-テスト仕様.md` | 確認項目・手順・期待結果 | テスト時 |
| `06-テスト結果.md` | 合否・実挙動・対応 | テスト時 |
| `07-トークン消費.md` | 消費量・原因/過程・改善案 | 完了時（必須） |
| `08-振り返り.md` | 知見・上流への還元候補 | 完了時 |
