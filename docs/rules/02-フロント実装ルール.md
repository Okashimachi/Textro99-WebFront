# 02 フロント実装ルール

textro99-web の実装コードを書くときのルール（AI に書かせる前提）。責務・原則は [01-責務と絶対原則.md](./01-責務と絶対原則.md) を前提とする。

---

## 1. コンポーネント分割

- **機能単位で分割し、1ファイルを小さく保つ。** 各コンポーネントは proto の DTO のみを入力とし、内部にゲーム判定ロジックを持たない。
- 構成イメージ（たたき台。最終形はクライアント担当マネージャーの判断）：
  `RawStateDebugPane` / `DakenDisplay` / `ComboGauge` / `DakenStackView` / `AttackWarningBar` / `PlayerGrid99` / `StrategySelector` / `EventLog`

## 2. RawStateDebugPane を最初に作る

- 受信 JSON をそのまま整形表示するペインを最初に用意する。
- AI 生成 UI にバグがあっても正データをここで常に確認でき、「サーバー(ロジック)のバグか表示のバグか」を即座に切り分けられる。

## 3. 状態管理

- **状態管理ライブラリを入れない**（useState/useReducer のみ）。状態の実体はサーバー側にあり、フロントは受信 state を写すだけ。Redux 等は不要。

## 4. 接続先URLは環境変数で切替

- 接続先 WebSocket URL（例 `VITE_WS_URL`）は **環境変数で切替**（ローカル / デプロイ版→本番サーバー）。**コードに直書きしない。**
- 本番URL・トークン等の秘密情報はコミットしない（→ [03-Git運用.md](./03-Git運用.md)）。

## 5. proto はバージョンを固定して参照

- 契約は [`@okashimachi/textro99-proto`](https://github.com/Okashimachi/Textro99-Proto)（GitHub Packages）を **バージョン固定**で参照し、任意のタイミングで上げる（勝手に最新を追わない）。互換表は Proto の README。
- **型の同期は人間が責任を持つ。** proto の DTO が変わったら同じタイミングで参照バージョンを上げ、影響箇所を直す。AI への指示時は必ず proto の型をコンテキストに含める。

## 6. 開発用起動モード（サーバー側）

- サーバー（Go）は `--mode solo`（1クライアントで戦闘ロジック単体デバッグ）/ `--mode match`（本番相当の同期）で起動できる。Web はどちらにも同一エンドポイントで接続する。

## 7. AI にロジックを"親切に"実装させない

- AI が気を利かせて戦闘ロジックを書いてしまう事故を、コード規約コメントとレビューで防ぐ。**レビュー観点は「打鍵判定以外のロジックが混入していないか」に絞る。**
