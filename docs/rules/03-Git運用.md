# 03 Git運用

commit / push / PR を行う前に読む。

---

## 1. ブランチ構成

```
main
 └─ develop          ← PR のベースブランチ
     └─ feature/xxx  ← 作業ブランチ
```

## 2. Git ポリシー

- **`git push` / PR 作成は自由に実行してよい**（人間の指示を待たなくてよい）。
- 作業ブランチ → 統合ブランチ（`develop`/`main` 以外）へのマージも自由に実行してよい。
- **`develop` / `main` へのマージは絶対禁止**（人間が行う。会話中に指示があっても実行しない）。

## 3. コミット規約

- 形式: `{type}: {概要}`。**1行で読める長さ（概要は日本語 20〜30文字目安）**に収める。
- type 例: `feat` / `fix` / `refactor` / `docs` / `chore`
- 原則**サブジェクト1行のみ**。詳細は worklog に書き、コミット本文は付けない（必要な時だけ短く）。
- 「コミットして」と言われたら、意味単位で複数コミットに分割する。
- 例: `feat: proto型を手コピーで取込` / `docs: worklog log-001を起票`

### コマンド構文の注意（Git Bash）

- Git Bash は POSIX sh。**PowerShell のヒアストリング `@'...'@` は使わない**（先頭・末尾にリテラル `@` が混入する）。
- 短い1行は `git commit -m "feat: 概要"`。改行が要る時のみ `$'一行目\n三行目'` かヒアドキュメントを使う。

## 4. 禁止コマンド（明示的な指示がない限り実行しない）

```
git reset --hard
git rebase -i
rm -rf
```

## 5. 秘密情報をコミットしない

- `.env` など秘密情報（接続先の本番URL・トークン・APIキー）をコミットしない。
- `.gitignore` に `.env` 系を必ず含める。
