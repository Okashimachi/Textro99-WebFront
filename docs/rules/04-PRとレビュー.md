# 04 PRとレビュー

PR（プルリクエスト）を出す・レビューするときのルール。ブランチ/コミットの基本は [03-Git運用.md](./03-Git運用.md)。

---

## 1. PR の流れ

1. `feature/xxx` で作業し、[03-Git運用.md](./03-Git運用.md) のコミット規約に沿ってコミットする。
2. `develop` をベースに PR を作成する（`main` 直接は禁止）。**PR 作成は AI が自由に実行してよい。**
3. PR 本文は [PRテンプレート](../../.github/PULL_REQUEST_TEMPLATE.md) に沿って埋める。
4. **`develop` / `main` へのマージは人間が行う**（AI は指示があってもマージしない）。

## 2. PR の粒度

- 1 PR は 1 つの関心事に絞る（レビュー可能な大きさに保つ）。
- 対応する作業ログ（[docs/worklog/](../worklog/README.md) の `log-NNN-*`）があれば PR 本文からリンクする。

## 3. レビュー観点（このリポジトリ固有）

このリポジトリの最重要レビュー観点は **「打鍵判定以外のロジックが混入していないか」**。以下を必ず確認する。

- [ ] 戦闘ロジック（コンボ/威力/相殺/スタック/KO/ターゲティング/難易度）を JS/TS で計算していないか（サーバー権威）→ [01](./01-責務と絶対原則.md)
- [ ] 打鍵判定の結果を `DakenClearReport`（ダケン単位）に集約しているか（1文字ごと送信・勝敗数値のローカル算出をしていないか）
- [ ] ローマ字テーブルを独自に持っていないか（Proto の共有データを使っているか）
- [ ] proto の型・契約をこのリポジトリで書き換えていないか（変更が要るなら Proto 側へ）
- [ ] 命名がユビキタス言語（用語集）に一致しているか → [01](./01-責務と絶対原則.md)
- [ ] 接続先 URL を環境変数で切り替えているか（直書きしていないか）
- [ ] 秘密情報（本番URL・トークン）が差分に含まれていないか
- [ ] コンポーネントが proto の DTO のみを入力とし、判定ロジックを内包していないか

## 4. マージ後

- `develop` へマージされたら、対応する作業ログの状態を ✅ 完了に更新する。
