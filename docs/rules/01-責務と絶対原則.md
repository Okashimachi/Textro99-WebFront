# 01 責務と絶対原則

textro99-web（Webテストフロント）の責務境界と、これに反する実装を書いてはならない絶対原則。**全作業の前提。**

上流の正典：[Textro99-Docs `04_クライアント仕様/02_Webフロント仕様.md`](https://github.com/Okashimachi/Textro99-Docs) / `01_コア設計書.md`、[Textro99-Client-Docs](https://github.com/Okashimachi/Textro99-Client-Docs)、[Textro99-Proto](https://github.com/Okashimachi/Textro99-Proto)。矛盾したら上流優先。

---

## このリポジトリが持つもの / 持たないもの

**持つもの:**
- WebSocket 接続・メッセージ送受信・受信ディスパッチ層（**Unity 流用の参照実装を兼ねる**）
- 受信 state を写す表示コンポーネント群
- 打鍵判定（TypingJudge）の TS 実装（クライアント唯一のローカルドメイン）
- 入力処理（文字キー / Enter / 0〜9）

**持たないもの（＝上流に委譲）:**
- 戦闘の数値ロジック（コンボ/威力/相殺/スタック/KO/ターゲティング/難易度）→ **サーバー権威（server / Textro99-Docs）**
- プロトコル契約そのもの（DTO/メッセージ/スキーマ/ローマ字テーブル）→ **Textro99-Proto**
- Web/Unity 共通のクライアント設計 → **Textro99-Client-Docs**

---

## 絶対原則（これに反する実装を書かない）

1. **JS/TS に戦闘・ゲームルールのロジックを書かない。** コンボ加減算・威力・相殺・スタック・KO・ターゲティング・難易度は一切クライアント禁止（サーバー権威）。
2. **唯一の例外は打鍵判定（TypingJudge）。** A案（コア設計書 2.3）により即応性のためローカル判定する。これはゲームルールではなく入力処理として許可する。
   - 判定は **Proto の共有ローマ字テーブルデータ**で実装し、Web/Unity 間の判定差異を作らない（データを二重管理しない）。
   - 判定結果は必ず **`DakenClearReport`（ダケン単位）** に集約して送る。**1文字ごとに送らない**。勝敗に関わる数値（コンボ等）はローカル算出せず、サーバーの `ComboUpdated` 等を反映するだけ。
3. **描画は必ず受信 state 経由。** 楽観的更新で戦闘値を先取りしない。打鍵の途中経過は画面表示にのみ使う。
4. **クライアントは外部DBを直接取得しない。** GameParameters はサーバーが取得し `MatchStart` の公開サブセットで配信された分だけ使う。
5. **プロトコル層は薄く contract 駆動に保つ。** proto の型に素直に対応させ、独自解釈やロジックを混ぜない。描画・入力（プラットフォーム固有部分）と明確に分離し、Unity 側のミラーが 1:1 で済む形にする。
6. **契約はこのリポジトリで変更・確定しない。** メッセージ/型/スキーマの変更が必要なら Proto 側の人間承認フローに回す。ここには「契約をこう使う」実装だけを書く。
7. **操作は2種のみ**：文字キー（打鍵）／0〜9（`StrategySelect`）。それ以外のキーは無視。攻撃はサーバーがダケンのノーミスクリアを起点に自動発火するため、クライアントから攻撃を送らない（`AttackRequest` は proto v0.1.1 で廃止・server #77）。
8. **命名はユビキタス言語（用語集）に合わせる。** 変数・型・コンポーネント・関数名は [用語集](https://github.com/Okashimachi/Textro99-Docs/blob/main/01_企画/00_用語集.md) の「コード上の名称」に一致させる（`Daken` / `DakenId` / `Combo` / `ComboBank` / `TypingJudge` / `RomajiTable` / `DakenStack` 等）。日本語会話用語を勝手に英訳して独自命名しない。テーマ（寿司モチーフ）変更時も**コード上の名称は変えず、表示名だけ差し替える**（表示名と概念名を分離する）。

## してはいけない設計（チェックリスト）

- ❌ JS/TS に戦闘ロジック（コンボ/威力/相殺/スタック/KO/ターゲティング/難易度）を書く（打鍵判定以外のローカルドメインを作らない）
- ❌ 打鍵を1文字ごとに送信する／勝敗数値をローカル算出する（`DakenClearReport` ダケン単位に集約する）
- ❌ ローマ字テーブルを独自に持つ（Proto の共有データを使う）
- ❌ 契約（メッセージ/型/スキーマ）をこのリポジトリで変更・確定する（Proto 側で人間承認）
- ❌ プロトコル層に独自解釈・ロジックを混ぜる（薄く contract 駆動に保ち Unity ミラーを 1:1 にする）
- ❌ 上流（Docs/Proto/Client-Docs）と矛盾する内容をこのリポジトリに残す（上流優先で直す）
